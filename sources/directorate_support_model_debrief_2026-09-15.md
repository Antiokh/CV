## Support transformation

Anton recalls that the Directorate's user support initially relied heavily on telephone calls. A single call could occupy a support specialist for roughly an hour while providing limited context and making parallel support effectively impossible.

Anton changed the support model to browser-based chat support using **tawk.to**.

The new model allowed the support team to:

- handle multiple conversations concurrently rather than one phone call at a time;
- work with roughly **10–15 parallel support sessions** during busy periods;
- see user/context information directly in the support interface;
- use visual / screen context to diagnose user problems more quickly;
- support institutions without forcing each issue through a long sequential telephone conversation.

Executive interpretation:

- support-channel redesign rather than simple tool substitution;
- materially increased support concurrency and operator leverage;
- reduced queueing caused by one-to-one phone support;
- improved diagnosis by adding user and visual context;
- helped make support scalable across a 100+ institution environment.

Potential CV-safe phrasing:

> Replaced sequential hour-long phone support with browser-based assisted support that enabled roughly 10–15 concurrent sessions and richer user context, making support materially more scalable across the institutional network.

Avoid presenting 10–15 concurrent sessions as product high-load; the value is **service-team leverage and support scalability**, not systems throughput.
